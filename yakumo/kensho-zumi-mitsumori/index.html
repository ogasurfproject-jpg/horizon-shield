検証済み見積もり
見積書に、あなたが自分では作れない証明を添える

「うちの見積もりは適正です」と、売り手が自分で証明することはできません。どれだけ誠実に積算しても、それは言い値として受け取られます。この商品は、その一点だけを解きます。見積もりが提示される前に第三者が記録した適正価格を、あなたの見積書に添えられる形で発行します。

なぜ売り手には作れないのか

適正価格の記録は、あなたの見積もりより先に存在しています。第三者が観測し、SHA-256で指紋を取り、Bitcoinブロックチェーンに固定したもの。後から都合よく作ることも、書き換えることもできません。売り手が自力では獲得できない種類の証明です。

何が変わるか

値引き交渉そのものが無くなるわけではありません。変わるのは、交渉が何を巡って行われるかです。

これまで
「他社はもっと安かった」

根拠が提示されないまま、金額だけが比べられます。誠実に積算した会社ほど不利になり、説明の言葉を尽くしても、それは売り手の主張として割り引かれます。結果として、下げるか失注するかの二択に追い込まれます。

検証済み見積もりを添えた場合
「この工事の適正はいくらか」

第三者が事前に記録した参照レンジが、判断の土台になります。あなたの金額がその中に収まっていれば、それは主張ではなく照合結果です。話題が「安いか高いか」から「適正か」に移ります。

施主は、あなたを信じる必要がありません

ここがこの商品の中心です。施主は発行元も信じなくて構いません。自分の手元で計算して確かめられます。

発行されたレシートには verify_url が付きます。施主がそのURLを開くと、施主自身のブラウザがSHA-256を計算し直し、レシートに記録された指紋と一致するかを照合します。値が1文字でも書き換えられていれば、一致しません。サーバーには何も送信されません。

レシートの中身（実際の形） { "fair_price_claim": { "work": ..., "unit": ..., "fair_min": ..., "fair_avg": ..., "fair_max": ..., "issued_at": ... }, "verification": { "claim_sha256": "改ざん検知用の指紋", "verify_url": "https://shield.the-horizons-innovation.com/verify/?id=...", "ptka": "Bitcoinブロックへの固定記録" }, "provenance": { "curated_by": "大賀俊勝 建設実務30年 監修", "recompute": "SHA-256を自分で計算して照合できる", ... } }
これは「信用してください」ではありません。

「信用しなくていいので、計算してください」という提示です。施主にとって、売り手の言葉より強いのはこちらです。そして売り手にとっても、疑われた時に差し出せるものがあるという意味を持ちます。

よくある質問

見積書の中身を提出する必要がありますか

必要ありません。渡すのは工事内容に対する適正レンジの記録です。見積書そのものや原価は発行元にも施主にも渡りません。

自社の金額がレンジより高い場合はどうなりますか

レシートは適正レンジを記録するもので、御社の金額を評価するものではありません。レンジより高い理由がある工事は当然あります。その場合、レシートは「なぜ高いのか」を説明する土台になります。根拠が無いまま高い場合には、それが露呈します。この商品は都合の良い数字を作る道具ではありません。

施主に「この会社が作った数字でしょう」と言われませんか

その反論は正しく、だからこの設計になっています。数字を信じてもらう必要はありません。施主は自分のブラウザで指紋を計算し直せます。加えて記録はBitcoinブロックチェーンに固定され、元になった相場データはDOI付きのオープンデータとして公開されています。発行元を信用しない立場のまま検証できます。

成約率は上がりますか

数字としては保証しません。実績データが出るまで、効果を数値で約束することはしません。確実に言えるのは、これまで差し出せなかった「売り手が自分では作れない証明」を差し出せるようになる、という一点です。
