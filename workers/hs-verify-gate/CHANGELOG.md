# hs-verify-gate changelog

Entries start at 0.4.24. Earlier versions are described in the CONFIG.version comment of src/worker.js and in GET /spec.

## 0.4.24 (2026-11-06)

How the gate calls an MCP endpoint now follows the Streamable HTTP transport. Gate 0.4.22 and earlier sent Accept: application/json only (without text/event-stream), read every answer as JSON and so could not read an answer sent as text/event-stream (SSE), sent initialize with protocolVersion only (without capabilities and clientInfo), did not carry Mcp-Session-Id, and sent neither notifications/initialized nor MCP-Protocol-Version. Because of this, the gate has written "MCP endpoint did not pass" for some Streamable HTTP servers that follow the specification (answers such as http 406, a response that is not JSON, an error on the initialize params, or http 400 for a missing session). From 0.4.24 every POST carries Accept: application/json, text/event-stream; initialize carries protocolVersion (the newest version the gate speaks, 2025-11-25), capabilities and clientInfo; the gate follows the version the server returns and sends it as MCP-Protocol-Version; it carries Mcp-Session-Id when one is issued, sends notifications/initialized, and closes the session with DELETE at the end (the close never affects the verdict); it reads a text/event-stream answer up to 2 MiB and within the same time limit as before, and when a limit is reached it writes "could not read to the end" and never writes a pass. The verdict rules, the status meanings, the conditions and the record_sha256 recompute recipe are unchanged. A server that still answers 406, a body that is not JSON, or a params error when called this way is recorded as before, and the reason now says how the gate called. Past records are not deleted; the sweep measures each endpoint again. The gap was found by our own checks, not reported from outside.
