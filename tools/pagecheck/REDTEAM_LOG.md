# Red Team Log

門(pagecheck)自身の欠陥ログ。見つけた穴と、いつ塞いだか。

HORIZON SHIELD は THROUGH-LIST で「落ちたものを消さず、取り消し線で残す」。
同じ規律を検証器自身に向ける。門にも穴はあった。隠さず、ここに残す。
自分に同じ物差しを当てないなら、他人を測る資格はない。

## 2026-08-30 ・ 第2回レッドチーム (敵をクラスに上げる)

第1回の13手は、門が「その13手」を弾くことしか証明していない。
敵を「毒 x 置き場所 x 符号化」の機械生成に上げ (1,475手)、門を個別対応でなくクラス単位に組み直した。
2撃で **10手がすり抜けた**。同日すべて修正し、1,475 / 1,475 を BLOCK (対照 20手は PASS)。

### 第1撃 (v1.1.0 の門を、v2 の敵で)
v1.1.0 の門を v2 の敵 1,475手で測ると **277 / 1,475** (1,198手がすり抜け)。内訳は
ダッシュ 220 / MOAT 449 / 金額 480 / 構造 49。個別対応の門は、符号化を1つ変えるだけで抜けた
(エンティティ / 全角 / ゼロ幅 / 同形異字 / 属性・meta・JSON-LD・CSS・JS への置き場所替え /
robots・canonical の書き分け)。この数字は誰でも再計算できる:
validate.py を v1.1.0 (git show e9d89c54:tools/pagecheck/validate.py) に戻して redteam.py v2 を走らせればよい。
正規化層と汎用タグ解析を入れた後、なお **4手** が残った:

| # | 攻撃 (難読化) | 旧門 | 修正後 |
|---|---|---|---|
| 1 | 通貨コード (JPY / yen / USD) をインライン要素で1文字ずつ割る (1<i></i>,<i></i>2… JPY) | すり抜け | BLOCK (糊付け本文) |
| 2 | 同上の別表記 | すり抜け | BLOCK |
| 3 | 同上の別表記 | すり抜け | BLOCK |
| 4 | JSON-LD の \u エスケープで MOAT 値を「32　.　5」(全角空白) に | すり抜け | BLOCK |

4番目は門自身のバグだった: JS の \u 復号が 4桁固定でなく 1〜6桁を貪欲に食い、
　5 を U+30005 と読んで見失っていた。門の復号器の欠陥が、敵に見つかった。

### 第2撃 (v1.2.0 の門を、さらに敵として攻める)
矩陣の外から、構造で殴る手を足した。**6手** がすり抜けた:

| # | 攻撃 | 旧門 | 修正後 |
|---|---|---|---|
| 5 | 外部 script src (許可外の出どころ) で実行時に描く | すり抜け | BLOCK (出どころ許可制) |
| 6 | 相対パスの script src | すり抜け | BLOCK |
| 7 | 同一リポジトリ内の JS に金額を置き、ページからは src で呼ぶ | すり抜け | BLOCK (JS の中身も門に通す) |
| 8 | 同上、MOAT語 | すり抜け | BLOCK |
| 9 | 同上、禁止ダッシュ | すり抜け | BLOCK |
| 10 | 実在しない同一リポジトリ内 JS を src で指す | すり抜け | BLOCK |

原因は一つ: タグ解析の前に script 要素を丸ごと剥がしていたため、script src の存在自体が見えなかった。
「JS の中は見ない」という設計判断が、「JS の出どころも見ない」に化けていた。

第2撃で最初から BLOCK だったもの (回帰確認): インライン SVG の CDATA 内の金額・MOAT、
alt 属性内の > による切断、unavailable_after、http-equiv X-Robots-Tag、noscript 内の robots、
条件付きコメント内の robots、base64 の MOAT、通貨記号なしの「総額 1,230,000(税込)」。

### 対照 (誤検出の監視) で見つけた副産物
出どころ許可制を入れた直後、既存の公開ページ 12枚が RUNTIME_SRC_NOT_ALLOWED で落ちた。
原因は Cloudflare Web Analytics の beacon (static.cloudflareinsights.com) が全ページに入っていたこと。
事前の棚卸しは src="…" の二重引用符だけを見ていて、単一引用符の beacon を見落としていた。
正当な出どころとして許可に足した。回帰テスト (26枚) が無ければ、門が自分のサイトを止めていた。

### 門の外にある穴 (門では塞げない。隠さず書く)
- **CI の対象範囲**: pagecheck.yml は `git diff HEAD^ HEAD` で「最後の1コミット」しか見ていなかった。
  複数コミットをまとめて push すると、先のコミットで変わったページは門を素通りする。
  同日、push の before..after 全域 (PR は base...head) を見るよう修正。
- **配信との順序**: 門は push の後に走り、GitHub Pages の配信 (static.yml) は門と独立に進む。
  赤は「配信を止める」のでなく「配信された後に知らせる」。配信を止める門にするには、
  static.yml の Build の前に同じ検査を走らせる配線が要る (門が赤なら deploy が失敗する)。
  これは配信の設計変更なので、代表の判断で入れる。番人は勝手に入れない。
- **画像の中の文字**: 金額を画像にして貼れば門は見えない。OCR は持たない。
- **許可した出どころの外部スクリプト** が実行時に描く文字は見えない。出どころで縛るだけ。

修正は validate.py v1.2.0 / redteam.py v2 / pagecheck.yml。
再現: `python3 tools/pagecheck/redteam.py` (1,475 / 1,475 が正常。約3秒、決定論的)。

次にやること: conduct register (5条件、gate.horizonshield.dev) 側にも同じ「毒 x 置き場所 x 符号化」の敵を用意する。

## 第3回 2026-09-04 ・ 記事の面 (qa/ aeo/) を守備範囲に入れる (v1.3.0)

### きっかけ
souba.html の内部リンク修正 (2026-09-04) で qa/aeo 102 ページを門に当てたら 1,317 件で不適格。
内訳が UNKNOWN_NAMESPACE 102 / MONEY_ON_PAGE 102 / CANONICAL_MISMATCH 98 / SUSPECT_RELATIVE_LINK 760 で、
門が「加盟店の面」の規約を「記事の面」に当てて取り違えていた。同時に、Google に索引されない qa 53 / aeo 41 と
「門が知らない名前空間」が同じ集合だった。代表の決裁: 報告で広げ、実欠陥を潰し、blocking に上げる。

### やったこと
名前空間の種類 (member / content) を入れ、content は 4 点だけ読み替え (canonical 形 / 出典つき金額 /
逆リンクの宛先 / 実在する内部リンク)。member の判定は一字も変えない: 第2回の 1,475 手は全て同じ結果。
content 用の 21 手を足した。うち 1 手は member への漏れ検査: yakumo のページに /souba/ への href を置いても
金額は弾かれる。1,496 / 1,496。

### 実測 (148 ページ、取り違えを読み替えた後)
208 件、全部が実欠陥。NO_AUTHOR 90 / ROBOTS_TAG_COUNT 86 / SUSPECT_RELATIVE_LINK 18 / DUPLICATE_IN_BATCH 14。
aeo 91 ページのうち 86 に robots meta が無く 89 に author が無かった。同日に 90 ページへ差し、一覧ページの
裸相対 18 本を /aeo/ 付きにした (バックアップ tar と差分検証つき、変更行は差した meta と href だけ)。
壊れた内部リンク 0、出典のない金額 0。

### 門が見つけたが門では直せないもの
近似重複 14 組 = 22 ページ。可視本文 1,700〜1,850 字、対で 63〜73% 同文。
**22 ページ中 21 ページが Google の「クロール済み・未登録」に入っている。** 薄い雛形の焼き直しが索引されない理由で、
これは文章を書き直す仕事。CI は qa/aeo 全ページを毎回 report で走らせ、消えるまで 14 組を出し続ける。

### 正直に書く副産物
blocking にした最初の push 自身が、aeo の重複 1 組 (断熱工事 ⇔ 雨漏り修理) を両方含むため赤になる。
門が正しく働いた結果であり、その 2 ページを今回の push から外すか、赤を1回受けるかは代表の判断。

修正は validate.py v1.3.0 / redteam.py (content 21 手) / POLICY.md v1.3.0 / pagecheck.yml (qa/aeo を blocking + report)。
再現: `python3 tools/pagecheck/redteam.py` (1,496 / 1,496)、`python3 tools/pagecheck/validate.py --mode report --paths $(ls qa/*.html aeo/*.html)`。

## 第4回 (2026-09-04 夜) ・ 門の外に名前空間を残さない (v1.3.1)

### きっかけ
第3回で qa/aeo だけを content にした。同じ日に外部の検証者から、別の系統 (JIDEC の拒否記録) について
「1 ケースのために作った直しが兄弟のケースへ一般化されずに残っていた」という指摘を受けた。同じ型を自分の門に当てたら、
faq/ blog/ souba/ (576 ページ) がまだ門の外だった。

### 実測 (v1.3.0 のまま content 扱いにして)
faq 35/35 通る (近似重複 8 組)。blog 36/86、souba 52/455。落ちた大半は取り違え 3 種:
移転スタブ (meta refresh + noindex) を「表示先を差し替える道具」として 8 件ずつ弾いていた (blog 25 / souba 170)。
souba の領収ページが証拠ファイルへ裸相対で繋ぐのを弾いていた (80 本)。インライン JS の文字列連結 '+REVERSE+' を href と取っていた (57 本)。

### やったこと
redirect を content の中の種類として認める (refresh + noindex の両方。片方なら普通のページ)。スタブには毒検査と移転先の検査だけ。
裸相対はページのディレクトリから実在すれば可。content のリンクは script/style を剥いで見る。member は一字も変えない。
21 手を足して 1,517 / 1,517。member に三つ揃いのスタブを置いても refresh は禁止のまま (漏れ検査)。

### 取り違えを消した後に残った実欠陥と、同日の修正
souba: スタブ 170 に canonical が無い / 「全国版へ」の薄い県別 65 (noindex だが refresh 無し、386 字) / robots 無し 116 / author 無し 32 / </html> 無し 5
  → 382 ファイルに差した行だけ (canonical 235 / refresh 65 / robots 116 / author 32 / </html> 5)、削除 0。72 → 423 / 455
blog: author 無し 25 / robots 無し 21 → 25 ファイル。36 → 83 / 86

### 門が見つけて門では直せないもの (report に出続ける)
souba: em ダッシュ 31 ページ / 「32.5」が MOAT 語と同じ 1 ページ (公表統計かどうかは代表の判断) / 雛形の近似重複 74 組
blog: 出典なし金額 2 本 (150万円 / 980万円) / index の JSON-LD 無し / 近似重複 1 組。faq: 近似重複 8 組

### 教訓
「守備範囲を広げる」は 1 回で終わらせる。名前空間を足した瞬間に「門の外に残っている名前空間は何か」を数え、ゼロにしてから閉じる。
再現: `python3 tools/pagecheck/redteam.py` (1,517 / 1,517)、`python3 tools/pagecheck/validate.py --mode report --paths $(find qa aeo faq blog souba -name '*.html' | sort)`。
