# Red Team Log

門(pagecheck)自身の欠陥ログ。見つけた穴と、いつ塞いだか。

HORIZON SHIELD は THROUGH-LIST で「落ちたものを消さず、取り消し線で残す」。
同じ規律を検証器自身に向ける。門にも穴はあった。隠さず、ここに残す。
自分に同じ物差しを当てないなら、他人を測る資格はない。

## 2026-08-30 ・ 第2回レッドチーム (敵をクラスに上げる)

第1回の13手は、門が「その13手」を弾くことしか証明していない。
敵を「毒 x 置き場所 x 符号化」の機械生成に上げ (1,475手)、門を個別対応でなくクラス単位に組み直した。
2撃で **10手がすり抜けた**。同日すべて修正し、1,475 / 1,475 を BLOCK (対照 20手は PASS)。

### 第1撃 (v1.1.0 の門を、v2 の敵で)
v1.1.0 の門を v2 の敵 1,475手で測ると **277 / 1,475** (1,198手がすり抜け)。内訳は
ダッシュ 220 / MOAT 449 / 金額 480 / 構造 49。個別対応の門は、符号化を1つ変えるだけで抜けた
(エンティティ / 全角 / ゼロ幅 / 同形異字 / 属性・meta・JSON-LD・CSS・JS への置き場所替え /
robots・canonical の書き分け)。この数字は誰でも再計算できる:
validate.py を v1.1.0 (git show e9d89c54:tools/pagecheck/validate.py) に戻して redteam.py v2 を走らせればよい。
正規化層と汎用タグ解析を入れた後、なお **4手** が残った:

| # | 攻撃 (難読化) | 旧門 | 修正後 |
|---|---|---|---|
| 1 | 通貨コード (JPY / yen / USD) をインライン要素で1文字ずつ割る (1<i></i>,<i></i>2… JPY) | すり抜け | BLOCK (糊付け本文) |
| 2 | 同上の別表記 | すり抜け | BLOCK |
| 3 | 同上の別表記 | すり抜け | BLOCK |
| 4 | JSON-LD の \u エスケープで MOAT 値を「32　.　5」(全角空白) に | すり抜け | BLOCK |

4番目は門自身のバグだった: JS の \u 復号が 4桁固定でなく 1〜6桁を貪欲に食い、
　5 を U+30005 と読んで見失っていた。門の復号器の欠陥が、敵に見つかった。

### 第2撃 (v1.2.0 の門を、さらに敵として攻める)
矩陣の外から、構造で殴る手を足した。**6手** がすり抜けた:

| # | 攻撃 | 旧門 | 修正後 |
|---|---|---|---|
| 5 | 外部 script src (許可外の出どころ) で実行時に描く | すり抜け | BLOCK (出どころ許可制) |
| 6 | 相対パスの script src | すり抜け | BLOCK |
| 7 | 同一リポジトリ内の JS に金額を置き、ページからは src で呼ぶ | すり抜け | BLOCK (JS の中身も門に通す) |
| 8 | 同上、MOAT語 | すり抜け | BLOCK |
| 9 | 同上、禁止ダッシュ | すり抜け | BLOCK |
| 10 | 実在しない同一リポジトリ内 JS を src で指す | すり抜け | BLOCK |

原因は一つ: タグ解析の前に script 要素を丸ごと剥がしていたため、script src の存在自体が見えなかった。
「JS の中は見ない」という設計判断が、「JS の出どころも見ない」に化けていた。

第2撃で最初から BLOCK だったもの (回帰確認): インライン SVG の CDATA 内の金額・MOAT、
alt 属性内の > による切断、unavailable_after、http-equiv X-Robots-Tag、noscript 内の robots、
条件付きコメント内の robots、base64 の MOAT、通貨記号なしの「総額 1,230,000(税込)」。

### 対照 (誤検出の監視) で見つけた副産物
出どころ許可制を入れた直後、既存の公開ページ 12枚が RUNTIME_SRC_NOT_ALLOWED で落ちた。
原因は Cloudflare Web Analytics の beacon (static.cloudflareinsights.com) が全ページに入っていたこと。
事前の棚卸しは src="…" の二重引用符だけを見ていて、単一引用符の beacon を見落としていた。
正当な出どころとして許可に足した。回帰テスト (26枚) が無ければ、門が自分のサイトを止めていた。

### 門の外にある穴 (門では塞げない。隠さず書く)
- **CI の対象範囲**: pagecheck.yml は `git diff HEAD^ HEAD` で「最後の1コミット」しか見ていなかった。
  複数コミットをまとめて push すると、先のコミットで変わったページは門を素通りする。
  同日、push の before..after 全域 (PR は base...head) を見るよう修正。
- **配信との順序**: 門は push の後に走り、GitHub Pages の配信 (static.yml) は門と独立に進む。
  赤は「配信を止める」のでなく「配信された後に知らせる」。配信を止める門にするには、
  static.yml の Build の前に同じ検査を走らせる配線が要る (門が赤なら deploy が失敗する)。
  これは配信の設計変更なので、代表の判断で入れる。番人は勝手に入れない。
- **画像の中の文字**: 金額を画像にして貼れば門は見えない。OCR は持たない。
- **許可した出どころの外部スクリプト** が実行時に描く文字は見えない。出どころで縛るだけ。
