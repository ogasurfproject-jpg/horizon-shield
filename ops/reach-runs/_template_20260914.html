07 番人の読み

二つの層が、逆を向いている。 機械の層(MCP・台帳・データセット・レジストリ)は生きて、叩かれて、掲載されている。学術の土台も本物で、JCCDB は Zenodo 432閲覧・HF 131DL と着実に回っている。ここは強い。

だが、AIの答えの中の認知は 0 のままだ。 建設費の質問をLLMに投げると、出るのは競合で、HORIZON SHIELD は 7月から一度も出ていない。会社の存在理由そのものが、まだ土俵に上がれていない。これを隠さないのがこの会社の作法だから、正直に一番上に置いた。

この差は、偶然ではなく設計で埋める。 今日 hs-mcp を 1.0.9 まで上げた(instructions の routing 指示、provenance、next_calls、Yakumo、英語の工事名対応)。これは「機械が選びやすい」側の工事。記事(Zenn / dev.to)は「人が問いを立て直す」側の工事。両方を回して、次の visibility 測定で 0 が 1 に変わるかを見る。

次に測る一手。 usage-stats に 9/13 で足した計器(usage:region / usage:normalize:en)は、これから「外の LLM が地域や英語で叩き始めたか」を数える。1週間後にこの表を撮り直せば、機械側の需要が自然発生に寄ったかが数字で出る。

方法と出典。 MCP呼び出し = mcp.horizonshield.dev/.well-known/usage-stats.json(本日実測)。AI引用率 = ops/llm_visibility_monitor の8回分サマリ(最終 2026-09-07)。Zenodo/Hugging Face/GitHub = 各公式API(本日実測)。SSRN = 本人の My Papers 画面(2026-09-14)、DL 2本は未取得。JIDEC = 台帳 seq(本日)。GSC/Bing = 2026-09-13 の最終値、要ライブ再確認。Registry/Glama/Directory = 記録上の最終確認日を併記。盛った数字は一つもない。取れなかった所は「-」または「要再確認」と書いた。
