## 0. 何を入れたか(結論)

1. **Agent Card 署名(A2A 1.0 §8.4)**。JWS ES256、RFC 8785 の正規形(proto の形に写した card、signatures 抜き)。署名は **Worker では作らん**。鍵を持つ Mac で `workers/a2a-card-sign/sign.mjs` が **公式 @a2a-js/sdk の generator** で計算し、公式 verifier で確認してから、Worker のソースの `CARD_SIGNATURE` 定数(`/* @@CARD_SIGNATURE_BEGIN */` と `END` の間)を書き換える。Worker は鍵を持たず、公開鍵だけを `/.well-known/jwks.json` で配る。署名は正規 origin(custom domain)で配る card にだけ付く。workers.dev の別名は signatures 無し。5 worker(mcp / gate / ledger / jidec / femtech)。
   - 署名が覆うもの: A2A 1.0 の schema が知る全部、**`capabilities.extensions[].params` 込み** = 報酬開示が発行者の鍵に縛られる。覆わんもの: schema 外の鍵(top-level の compensation、ledger、dataset、0.3 の url/preferredTransport/protocolVersion)。公式 SDK の正規化がそれらを落とすから。README に書いた。
2. **扉 0.3.4: 相手の card の署名を読む(判定不変)**。条件 2 の `detail.signature` に `verified true / false / null(読めん)`、kid、jku、jku が card と同じ host か、正規形の sha256。扉の正規化(schema で書いた写し)が **公式 SDK の canonicalizeAgentCard と同じ bytes を出すこと**を `workers/a2a-card-sign/canon_equiv.test.mjs` が 27 例で確かめる(実測で分かった規則: string は "" を省く、`required:false` は省く、optional bool は false でも残す、空 message は省く、Struct は null / "" / {} / [] を再帰的に落として false と 0 は残す)。securitySchemes を持つ card は「検証できん」と言い、有効とも無効とも言わん。red team +8 → **82/82**。無効な署名で条件 2 を落とすかは判定規則の変更なので、ここでは決めとらん(記録には残る)。
3. **femtech の看板**: card を A2A 1.0 の形に(provider を object、skills に name/description/tags、defaultInput/OutputModes、supportedInterfaces [1.0, 0.3] と url が `/a2a`)。`/a2a` を足した(URL か発信元名を text part で渡すと check_source の答えを Message で返す。真偽も良し悪しも症状も扱わん)。root への A2A method も受ける(旧 card の url が root やった名残)。harness 34 green、公式 SDK 両線 ALL PASS。
4. **in-toto Statement v1 の発行**: `workers/hs-ledger/nenrin/ring-v1/ring_to_intoto.py`。仕様 6 節の写像を「方向」から「納品」に。subject = ring file の sha256、predicateType = 拡張の URI、predicate = ring の数(写すだけ、再計算せん)。`--key` で DSSE envelope(ES256、card と同じ鍵型)、`--verify` で検証。
5. **w3id の永続 ID**: `ops/w3id/README.md` に perma-id/w3id.org への PR の中身(`horizonshield/.htaccess`: `https://w3id.org/horizonshield/conduct/v1` → 302 → 扉の URI)。識別子は増やさん、便宜の転送。
6. **仕様の錨**: `workers/hs-ledger/make_conduct_ext_seed.py`(coordinate の seed と同じ流儀、fail-closed、9 節と 10 節が無ければ書かん)。sha 3aa5a50d を確認して seed を書いた(未 commit)。
7. **claim register の FAIL 2 件(別チャットからの報告)を直した**: C03 = 扉 /spec の red_team を「v0.3.4 scores 82 of 82」に(claim_register は最後の "scores N of N" を読む)。C16 = `workers/hs-verify-gate/server.json` を 0.3.4 に(publish は Actions、下記)。
