# 合意の記録層(取引所やない)と、金の取り方 2026-09-10 番人

TOshi の問い 2 つに答える。(1) 署名の無い agent を「落とさんだけ」で済ませてええのか。
(2) インフラを撮るなら agent 同士の取引所が要るんちゃうか。全ての取引が見えて、双方の合意で成立する場。

結論を先に。

1. 署名の有無で**合否は動かさん。動かすのは「その記録が何を証明するか」**。これは相手の穴やなく**うちの穴**やった。扉 0.4.4 で塞ぐ。
2. **取引所は作らん。** 金・与信・エスクローに触った瞬間、中立(紹介料を取らん)が死ぬ。作るのは**合意の記録層**で、金には一切触らん。
3. **有料にするのは「組み込む部分」やない。運営が要る部分や。** 組み込む所を有料にしたらインフラにならん。
4. 隣は空き地やない。**Cedulon(IETF 個人draft -08)と 1F916 Agent Record(同 -01)が既に居る。** ただし両方に穴があって、その穴がちょうどうちの持ち物で埋まる。

---

## 1. 署名の無い agent が意味すること

**(1) TLS が「取った瞬間」を既に押さえとる。** jku が同一ホストなら、署名は fetch の瞬間にはほぼ同語反復。署名が効くのは**持ち出した時と、時間が経った時**だけ。

**(2) せやから 署名無し = その宣言は持ち出せん。** 登録簿の「この endpoint は paid_by: buyer と宣言した」という行は、**相手の言葉やなく、うちの言葉**になる。相手はいつでも否認できる。

ここが痛い。**うちの看板は「信用が要らん」やのに、無署名の相手についての行は、読む側がうちを信用するしかない。** 0.4.1 でバイトを配ったから「うちが記録した」ことは証明できる。しかし「相手が公開した」ことは証明できとらん。**その差を記録に一言も書いてなかった。**

**(3) 名前と住所が分かれとらん。** 今の identity は endpoint の URL。ホストを握った者がその名前を定義し、ドメインが人手に渡っても行は名前を持ったまま残る。**ホストより長生きする鍵で署名して初めて、行為者と住所が分かれる。** 2026-09-09 に w3id でやった「識別子が Cloudflare より長生きする」の、相手側の版。

**(4) 署名を過大評価もせん。** 署名が証明せんこと: 鍵はホストが「ここにある」と言うた場所にある、法人が誰かは分からん、漏れた鍵も署名する、履行は何も言うてない。**署名 = 転送に耐える著者性、それだけ。**

**(5) 直し方(扉 0.4.4)。条件は増やさん。0.4.0 の establishes / does_not_establish を使う。**

- 無署名 → `does_not_establish` に:「この記録は、運営者がこの card を公開したことを証明せん。署名が無いので、このバイトはこの扉の観測に帰属するだけで、運営者は否認できる」
- 署名あり + 検証 OK → `establishes` に:「card のバイトは jku の鍵(kid)で署名されとる。この宣言は扉やなく運営者に帰属する」
- 署名あり + 検証不能(jwks 404 / 未知の kid / 他ホストの jku)→ どちらも書かず、試したことと取れんかったものだけ書く

赤くならん。点も出さん。**「あんたの行が何を証明するか」だけが変わる。** 署名する得を、罰やなく事実で作る。掟(内容は審査しない、開示せんという選択肢だけを消す)のそのままの形。

歩く側(walk client、第四波 4a-1)にも同じ 3 行を入れる。

## 2. 取引所は作らん。合意の記録層を作る

### 作ったらあかん物

注文をマッチングし、金を預かり、成立を宣言する場。理由 4 つ。

- 金を預かる = 資金決済法の世界。一人法人が背負える重さやない
- 手数料を取る = うちの compensation が `paid_by: transaction` になり、Yakumo の中立(紹介料を取らん)が死ぬ
- 成立を宣言する = 紛争が全部こっちに来る。扉は判定せんのが芯やのに、取引所は判定せなあかん
- 流動性ゼロ。外の card がまだ 1 枚も無い。空の取引所は無い方がマシ

### 作る物: `a2a-agreement-v1`(案)

今の conduct-v1 が記録しとるのは**片側の観測**(扉が測った、client が歩いた)。抜けとるのが**両側の出来事**。

- 中身: 当事者 2 者(ドメイン + 鍵の場所)、**その時点で互いに提示した conduct 記録の sha**、条件(何を、どっちがどっちに払う、料率、開示先)、合意時刻、上流の支払い参照(x402 の tx や AP2 の mandate id、任意)
- **受理規則: 片側だけの署名は受理せん。** 両方の署名が同じ正準バイトを覆っとることを intake が検算する(今の self_witness 拒否と同じ fail-closed)
- 錨: 既存の日次束ね → Bitcoin
- 輪に `agreements` 列(数えるだけ。率も点も順位も出さん)
- **証明せんこと: 履行、品質、法的効力、金が動いたかどうか**

**ここで 1 と繋がる。無署名の agent は、そもそも合意の当事者になれん。** 署名は成績やない、**約束できるかどうかの前提条件**や。門では落とさん。市場が決める。これが「落とさんだけではダメ」への答え。

### 一番効く一点

**合意のバイトの中に、その時点の相手の行儀の記録の sha を埋める。** 後で相手の記録が変わっても、**合意した時に何が本当やったか**が永久に残る。測定層と錨を両方持っとる者にしか書けん。ここが Cedulon にも 1F916 にも AP2 にも無い。

## 3. 外の地図(2026-09-10 実測)

| 層 | 誰が居るか | 穴 |
| --- | --- | --- |
| 金の実行 | x402(Coinbase + Cloudflare、本番の実績が最も強い)、AP2(Google、60 社超、mandate を双方署名)、ACP(OpenAI + Stripe)、MPP(Stripe + Tempo)。**A2A には `google-agentic-commerce/a2a-x402` 拡張が既にある**(payment-required → payment-submitted → payment-completed、Apache-2.0、experimental) | **第三者も監査ログも無い。** 合意した条件の記録は鎖の外に残らん |
| 1 者の agent の履歴 | **1F916 Agent Record**(IETF 個人draft-01、2026-08-12)。Ed25519 の追記専用ログ、**証人が checkpoint に副署**、CT / SCITT 型 | **意図的に錨を使わん**(blockchain 無し、信頼は証人の多様性のみ)。**扱うのは 1 者の履歴で、二者の合意やない**(本人が明記)。独立実装による検証器の再構築はまだゼロと自認 |
| 取引の監査(receipt 突合) | **Cedulon**(IETF 個人draft-08)。Spend Receipt(payer/payee/amount/policy hash/manifest hash/rail 参照/prevReceiptHash/outcome)。custody 禁止を明記 | **当事者が自分の記録を持つ** = 証明する側が座標を握る、うちが 3 軸で潰してきた欠陥そのもの。**副署は任意** = 片側だけの receipt が有効。外部の錨も相手の行儀も無し |
| **二者の合意 + 外部錨 + 相手の行儀** | **誰も居らん** | ここ |

うちが既に持っとる 3 つ(測定 = 扉、証人 intake = 台帳、Bitcoin の錨 = JIDEC)が、そのまま空白の要件になっとる。これは偶然やなく、順番に積んできた結果や。

**1F916 との違いは思想の違いで、優劣やない。** 向こうは「証人の多様性で改竄を検出する」、うちは「証人 + 誰も持っとらん時計」。並べて書く。喧嘩やない。

## 4. 金の取り方(TOshi の 2 つの動線への答え)

### (a) 各社の agent に仕組みを組み込む → **有料にしたらあかん**

組み込む部分(card の宣言、walk client、hook、仕様)は **Apache-2.0 のまま無料**。ここを有料にした瞬間、誰かが同じ物を無料で配って標準を取る。TLS のライブラリは無料で CA が有料、OpenTimestamps は仕様無料で calendar が運営、と同じ形。**広がる部分は無料、運営が要る部分が有料。**

### (b) 取引時に第三者として呼ばれて記録を取る → **これが本命**

呼ばれる第三者の条件は 1 つ。**双方から呼べて、どちらにも縛られとらんこと。** そのためには「片方が金を払っても、記録の中身が変わらん」ことを相手が確かめられなあかん。それはもう出来とる(hash、公開バイト、外部の錨)。**つまり今までの積み上げが、そのまま第三者になる資格や。**

**課金の線(絶対に越えん):**

- **記録する行為に対して課金する。定額かサブスクか 1 記録いくら**
- **取引額の割合や成立可否に連動させたら終わり。** `success_fee_pct > 0` になった瞬間、うちの条件3 の開示が「取引が成立したら儲かる」と言う。中立の看板が死ぬ
- **合意記録のバイトの中に「この記録の代金を誰が払ったか」を書く**(`record_paid_by`)。相手に課しとる条件3 を、うち自身が取引層で満たす。これが第三者性の証明になる

### 有料にしてええ物の一覧(今の段と地続き)

1. 証人 intake と錨の運用(束ね、stamp、保管)
2. 取引時の第三者記録(上の (b))
3. 相手の行儀の即時照会(register/lookup の商用ティア: リアルタイム、SLA、私的照会)。無料の 24h キャッシュ版は無料のまま
4. 企業の内部 agent を外から測る(自分では自分を測れん)
5. 既存の Verified+Data / Yakumo Partner

## 5. 「万能エージェント」について、番人の反対意見

**「なんでもできる万能」は目標として間違っとる。** 全部できると名乗る agent は、扉が狩る側の特徴そのものや。

うちの agent が強いのは能力の広さやない。**他の agent が「自分では作れん記録」を持っとるから、呼ばざるを得ん立ち位置**にあることや。強さ = 立ち位置(第三者性)であって、能力の幅やない。

幅を広げるほど利害が増え、第三者性が薄まる。**万能を目指すと、逆に呼ばれんようになる。** 狭くて、限界を自分で公開しとって、誰でも検算できる。それが結局いちばん遠くまで運ばれる。
