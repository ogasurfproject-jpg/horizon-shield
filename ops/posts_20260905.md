## LinkedIn(英語)

Picture the sticker on a restaurant door. Not a review, not a star rating. A health inspector came, measured a short list of things, and the sticker says so, with a date. Anyone can walk in without reading it. But a lot of people look.

AI agents now walk into other people's software the same way. Before an agent uses a tool server (the MCP kind), nobody checks a short list of things: does it actually speak the protocol, does it publish a card that says who it is, does it state who pays its operator, and does it answer the same question the same way twice.

We built the inspector. It is free, it does not sell the sticker, and every verdict carries a hash you can recompute on your own machine, so you never have to trust us. Our own servers are on the same register and can fail on it.

Yesterday we removed ourselves from the loop. Three doors, none of which need a human at HORIZON SHIELD:

The server owner puts one small file on their own domain, at /.well-known/mcp-conduct.json. Only the owner can place it, so the inspector treats it as permission and measures everything, on a schedule.

The developer adds one step to their CI (mcp-conduct-action on GitHub). Every push gets measured, and the hash is recomputed right there on the build machine.

The agent adds one line before it connects. It is on npm as mcp-conduct, zero dependencies: npm i mcp-conduct. Read the sticker, then decide, with a policy you choose.

Honest position: as of today the register holds our own servers and nobody else's. The doors are open; the first outside row has not walked through. If you run an MCP server, the check is one POST and takes a minute. I would rather you check it than believe me.
