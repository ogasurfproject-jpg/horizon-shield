## 0. 何を直したか

| | 0.3.4 までの本番 | 0.3.5 |
|---|---|---|
| A 履歴 | 判定には coordinate_derivation が載るが、summarise() が落とすので /history には 1 バイトも残らん | 全 /history entry に coordinate_derivation(derived、window_id、salt_commitment、beacon の高さと hash と header time、day_in_window、tool_set_sha256、落ちた時は fallback と reason_code と why) |
| B 一致判定 | 源ごとに自分の tip - 6 の高さと hash の完全一致。2 つの explorer の tip が 1 本ずれた瞬間に落ちる | 基準高さは 1 つ: 答えた源の 2 番目に高い tip - 6(freshness v3.3 の quorum tip、2 源なら min(tip) - 6)。その高さの hash が 2 源以上で一致すれば採る。源は 3 つ(mempool.space、blockstream.info、mempool.emzy.de、後の 2 つの mempool は同じ codebase = 残る軸) |
| C 順序 | 掃引の頭で salt を作り、その瞬間の tip - 6(約 1 時間前の block)に束縛 = salt が block の後 | 次の窓の salt を今の窓の掃引で先に作る。beacon の block は header time が salt_created_at 以上でなければ採らん(time が読めん時も採らん)。commitment は GET /nenrin/window で作った瞬間から公開。台帳への錨打ちは次段(未実装と明記) |
| D 固定 | beacon が失敗すると翌日も再試行するので、窓の途中で legacy から derived に切り替わり得た(同じ窓で 2 回測られる行と 1 回も測られん行) | 窓の最初の掃引で決めた規則(derived か legacy)をその窓に固定。固定した事実と理由を /nenrin/window と /sweep/last に出す |
| 公開面 | 無し | GET /nenrin/window(今、次、前の窓)、GET /nenrin/window/{wid}、閉じた窓は salt を reveal。運営者専用 GET /nenrin/probe(x-sweep-token、KV に書かず beacon を試し引き) |
| 数 | red team instant 26、gate 82 | instant 40、gate 82、新規 sweep_coordinate 22。/spec の instant_coordinate に「2026-09-06 に見つかった 3 つのズレ」を日付付きで残した |
