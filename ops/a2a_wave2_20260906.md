## 0. 何を直したか(結論)

公式 SDK で実測した(ネットワーク無し、本物の worker のコードに公式 client を当てた)。

- `@a2a-js/sdk` 1.1.0 の既定設定は、うちの KIRA の card(0.3 形)から **client を作れん**(「No compatible transport found」)。legacyCompat を明示した client だけ繋がり、そいつは `X-A2A-Extensions` を送るから、うちの echo は **出とらんかった**。18 項目中 14 落ち。
- `a2a-sdk`(Python)1.1.2 は互換路で両綴りを送るから echo は出とったが、1.0 の interface は見えず、`Message.extensions` も無かった。4 落ち。
- hs-ledger の card は `supportedInterfaces[0].transport`(1.0 の鍵名は `protocolBinding`)で、公式 SDK は interface を選べんかった。/a2a は 1.0 形の part(`kind` 無し)を「invalid params」で弾いとった。
- hs-jidec-mcp と扉の card の `url` は A2A を喋らん場所を指しとった(看板が嘘)。

直した後: JS / Python の公式 SDK、1.0 と 0.3 の両線、4 worker(hs-mcp, hs-ledger, hs-jidec-mcp, hs-verify-gate)、全部 ALL PASS。

中身(全 worker 共通):
1. 拡張ヘッダは両綴りを読む(`A2A-Extensions` と `X-A2A-Extensions`)。echo は常に `A2A-Extensions`、要求が X- 綴りならその綴りでも返す。
2. 線の版は method 名で決める(`SendMessage` = 1.0、`message/send` = 0.3)。1.0 は `{task}|{message}` に包み、`TASK_STATE_*` / `ROLE_*`、part は `kind` 無し。0.3 は従来のまま。
3. 拡張が有効なら `metadata` の 3 鍵に加えて `Message.extensions` に URI(A2A 本体の欄)。
4. card は `supportedInterfaces`(1.0 が先、0.3 が後、`protocolBinding`)と 0.3 の `url`/`preferredTransport`/`protocolVersion` を同居。
5. hs-jidec-mcp に `/a2a`(jidec_cite を Message で返す)。扉に `/a2a`(text の URL の register の読み = GET /is-verified と同じ bytes を Message で返す)。扉 0.3.3。
6. 仕様 3 節・4 節に線の注記、10 節「License and governance」(Apache 2.0)、`ext/LICENSE`。仕様 sha **3aa5a50d8ac323c63951bdf4b73d6fa1de6a45aa0d0a41dced4792d5f6dfafd8**(2,404 語)。
7. walk client に `--wire 1.0|0.3`。0.3 walk は `message/send` + `X-A2A-Extensions` だけを送る(0.3 client と同じ振る舞い)。selftest 17 → 22。

判定規則(扉の 5 条件)は一切触っとらん。red team 74/74 のまま。
